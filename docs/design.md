# Дизайн-система «Учёбы»

Это правила внешнего вида приложения. Все новые экраны (замены, ДЗ, заметки, экспорт) строятся по ним.
Если правило мешает, его меняют здесь, а не обходят в отдельном экране.

Посмотреть всё вживую: страница превью `preview/` (на сайте: `https://irequ1ern-oss.github.io/-/preview/`).

## 1. Принципы

- **Как iOS.** Основа — iOS 17–18: большие заголовки, сгруппированные списки как в «Настройках», системные серые фоны,
  тонкие разделители с отступом слева. Из iOS 26 (Liquid Glass) берём **стекло только для навигации**:
  нижняя капсула вкладок, верхняя панель экрана, боковое меню планшета, всплывающие уведомления.
- **Контент непрозрачный**: списки, карточки, шторки читаются на любом фоне.
- **Один акцент — вишнёвый.** Им окрашены кнопки, активная вкладка, «+», переключатели, ссылки.
  Красный используется только для ошибок, просрочки и удаления.
- **Цвет — у предметов.** Каждый предмет узнаётся по цветной иконке-«squircle» с белым знаком.
- **Никаких эмодзи** в интерфейсе: только иконки Phosphor.
- **Шрифт Inter** (локально, без интернета). SF Pro и SF Symbols не используем: лицензия Apple разрешает их только на устройствах Apple.

## 3. Токены

Правило: **в компонентах нет цветов, теней и размеров «вручную»**, только `var(--…)` из `tokens.css`.
Тест `src/ui/tokens.test.ts` проверяет контраст (WCAG AA ≥ 4.5:1) во всех темах, а `src/ui/style-rules.test.ts` — что
в CSS-файлах компонентов нет цветов в обход токенов.

### Темы

Атрибут `<html data-theme="light|dark|amoled">`. Режим «Авто» выбирает светлую или тёмную по системе
(`src/state/settings.ts → applyTheme`). Там же обновляется цвет строки состояния (`meta theme-color` = `--bg`).
Ещё до загрузки скриптов тему и цвет строки состояния ставит маленький скрипт в `index.html` (без белой вспышки);
что его цвета совпадают с `--bg`, проверяет тест.

| Тема | Фон `--bg` | Карточки `--surface` | Особенности |
| --- | --- | --- | --- |
| Светлая | #F2F2F7 (systemGroupedBackground) | белые | лёгкие тени карточек |
| Тёмная | #121214 (графит) | #1E1E22 | без теней |
| AMOLED | #000000 | #0C0C0E | тонкие границы `--border`, бережёт батарею OLED |

### Цвета (смысл)

| Токен | Для чего |
| --- | --- |
| `--bg` | фон экрана |
| `--surface` | карточки, строки списков, шторки внутри |
| `--surface-2` | вторичная заливка: фон сегментов, полей, нажатая строка |
| `--surface-3` | третья: выключенный тумблер |
| `--segment-thumb` | бегунок сегментированного переключателя (в тёмных темах заметно светлее дорожки) |
| `--separator` | разделители 0.5px |
| `--border` + `--border-w` | граница карточек: `border: var(--border-w) solid var(--border)`. Толщина 0 в светлой и тёмной, 1px в AMOLED — так рамка не съедает место |
| `--label` / `--label-2` / `--label-3` | основной / вторичный (AA) / третичный текст (только подсказки, не для важного) |
| `--accent` | вишнёвый для текста и значков |
| `--accent-fill` + `--on-accent` | заливка кнопок и белый текст на них (AA) |
| `--accent-tint` | полупрозрачный вишнёвый фон (активная вкладка, выделение) |
| `--danger`, `--success`, `--warning` (+ `-fill`) | ошибка/удаление, «сделано», «замена/внимание» |
| `--ring-track` | дорожка колец и полос прогресса |
| `--overlay` | затемнение под шторкой и меню |
| `--sheet-bg` | фон шторки (в AMOLED чуть светлее чёрного, чтобы шторка лежала «над» страницей) |
| `--aside-bg` | фон колонки «Ближайшее» на планшете: темнее карточек внутри неё |
| `--glass-*` | стекло навигации; `--glass-bg-solid` — непрозрачная замена, если браузер не умеет размытие |
| `--sc-<цвет>` | 13 цветов предметов (свои значения для светлой и тёмных тем) — для колец, точек, полосок |
| `--sc-<цвет>-tile` | фон плитки-иконки для самых светлых цветов (жёлтый; в тёмных ещё мятный, голубой, бирюзовый): чуть глубже, чтобы белый знак читался. Брать как `var(--sc-X-tile, var(--sc-X))` |
| `--glyph-shadow` | едва заметная тень белого знака на плитке (`filter`) |

Вишнёвый: светлая тема `#911E42` (классический «вишнёвый», и текст, и кнопки); тёмные — текст `#E0698D`, кнопки `#A8264E`
(светлее для текста, иначе он не читается на тёмном фоне; кнопки темнее, чтобы белый текст на них проходил AA). В светлой теме оранжевый (`--warning` #8F4900) и красный (`--danger` #B8000E)
темнее системных iOS: иначе метки «замена» и «отменена» на своём бледном фоне не проходят AA (тоже проверяется тестом).

Модификаторы: `.t-secondary` (серый), `.t-accent`, `.t-upper` (заголовки групп), `.tabular` — **обязательно для
времени и таймеров** (цифры одной ширины, не прыгают), `.nowrap` — не переносить внутри фразы («через 37 мин», «каб. 21»).
Цифры таймера в главном блоке — `--fs-timer` / `--lh-timer` (30 / 36).
Между числом и единицей — неразрывный пробел (`formatDuration`, `formatRoom` уже так делают).

### Отступы, радиусы, размеры

- Отступы: `--space-1…8` (4, 8, 12, 16, 20, 24, 32), поля экрана `--gutter: 16px`.
- Радиусы: `--r-group` 14 (списки), `--r-card` 22 (крупные карточки), `--r-sheet` 28 (шторки), `--r-pill` (капсулы),
  `--r-segment` / `--r-segment-thumb` 10 / 8 (сегменты),
  иконки предметов — `--r-icon` 22.5% от размера («squircle»).
- Минимум для нажатия: `--tap-min` 44×44. Иконки предметов: `--icon-sm` 29 (списки), `--icon-lg` 44 (крупные блоки), 64 (карточка предмета).

### Анимации

- Кривая `--ease-ios: cubic-bezier(0.32, 0.72, 0, 1)`, длительности `--dur-1` 200, `--dur-2` 320, `--dur-3` 450 мс.
- Анимируем **только `transform` и `opacity`** (60 кадров на телефоне). Ширина и положение блоков меняются сразу,
  а движение делается сдвигом: например, сворачивание бокового меню — два стеклянных слоя (сдвиг + прозрачность)
  и сдвиг колонки экрана по принципу FLIP (`useSlideOnCollapse` в `AppShell`).
  Допустимые исключения: подсветка фона при нажатии и кольцо таймера (`stroke-dashoffset`) — они не пересчитывают раскладку.
- `prefers-reduced-motion` → длительности 1 мс, нажатие без уменьшения (токены сами переключаются).

## 4. Предметы: цвет, иконка, сокращение

- В коде предмет берём только так: `const s = useSubject(id)` → `s.short`, `s.full`, `s.color`, `s.icon`, `s.teacher`.
  Это уже учитывает настройки пользователя.
- Цвет на экране: `var(--sc-${s.color})`. Иконка: `<SubjectIcon color={s.color} icon={s.icon} size={29|44|64} />`.
- **Автоподбор цвета** (`src/core/colors.ts`): предметы одного дня и пары подряд получают заметно разные цвета
  (ΔE ≥ 30 **и в светлой, и в тёмной теме** — берётся меньшее из двух; тест проверяет это на настоящем расписании),
  сначала используется вся палитра. Красный, розовый и серый автоматически не выдаются (можно выбрать вручную).
  Сейчас так: Ин. яз — жёлтый, Физра — оранжевый.
  Цвет и иконку по умолчанию можно задать в `data/schedule.json` (поля `color`, `icon`).
- Кабинет пары: `lessonRoom(lesson, settings.subgroup)` + `formatRoom()` → «каб. 27», «Спортзал».

## 5. Иконки

- Набор **Phosphor** (MIT). Контур (`weight="regular"`) — обычное состояние, заливка (`weight="fill"`) — активное
  (активная вкладка, иконки предметов, плашки настроек).
- В приложение попадают только нужные иконки: список в `scripts/gen-icons.mjs` → `node scripts/gen-icons.mjs`.
- Иконка без подписи обязательно с `aria-label` (у `IconButton` это проп `label`).
- Строки настроек: `<IconTile name="palette" color="indigo" />` (белый знак на цветной плашке, как в «Настройках» iOS).
- Плитки (`SubjectIcon`, `IconTile`) берут фон `var(--sc-X-tile, var(--sc-X))` и тень знака `--glyph-shadow`.
- Знак должен читаться в заливке: у ОБП — `trend-up` (линия со стрелкой), а не `chart-line-up` (в заливке это сплошной квадрат).
- Выбор иконки в настройках: невыбранные — нейтральные плитки (`--surface-2`, знак `--label-2`), цветная только выбранная,
  рамка выбора — `--label`. Цвета и иконки — группы переключателей: один Tab на группу, стрелки двигают выбор.

### Главный блок «Сегодня» (`views/today/Hero.tsx`)
- Подстраивается под ширину, которую реально получил (container query на `.hero-box`), а не под тип устройства:
  обычно кольцо 136 px; уже 360 px (телефоны до ~390) — кольцо 112, поля поменьше; уже 300 — кольцо над текстом;
  шире 520 (планшет) — кольцо 168 и вся группа по центру.
- Фразы не рвутся: «Иди в каб. 21» переносится только перед «каб.», короткое название предмета — одной строкой.
- Подпись следующего дня: относительное слово только для завтра («Завтра, среда, 14 октября»), иначе «Понедельник, 19 октября».
  Заголовки списков — «Расписание на завтра / на понедельник» (без «послезавтра»).
- Перемена: под блоком «Позади 4 из 5» (слово «перемена» уже есть в блоке). До первой пары «Далее» не показываем —
  первая пара уже в блоке.
- Прошедшие пары свёрнуты в строку с серой плиткой `check-fat`.
- «Праздник» (конфетти и название периода) — только если во временном расписании нет пар вообще;
  свободный день внутри обычного временного расписания — «Выходной» или «Свободный день».

### Другие экраны
- «Неделя»: заголовок дня — «Сегодня, 12 октября» / «Четверг, 15 октября» (без отдельной метки).
  Диапазон в заголовке — по дням, которые реально показаны (с субботой — «12–17 октября»).
  Если на строке открылось меню долгим нажатием, свайп дня отменяется.
- «ДЗ»: оба кольца статистики — доли от всех заданий недели, подписи одинаковые: «2 из 6».
  «Перенести» ставит срок на следующую пару предмета после сегодняшнего дня (или после старого срока, если он ещё впереди).
- «Основное расписание»: один сгруппированный список дней; пары раскрываются под днём.
- «Заметки» и «ДЗ» до этапа 3: `EmptyState plain` в `Screen class="screen--centered"` — по центру свободного места.
- «Сегодня» с `?now=…` в адресе: под датой строка «Тестовое время · Сбросить» (`--warning`), чтобы не спутать с настоящим.

### Свайпы по строкам (`SwipeRow`)
- Как в «Почте» iOS: вправо — одно действие (`leading`), влево — до двух (`trailing`, первое — для полного свайпа).
- Кнопки действий шириной 80 px (`--swipe-action-w`), полный свайп срабатывает на 60% ширины строки.
- Открыта только одна строка; Tab на кнопку действия тоже открывает строку (доступно без жестов) — только при фокусе
  с клавиатуры: фокус, который вернула закрытая шторка, строку не открывает.
- Опасное действие — с `confirm: { title, confirmLabel }`: сначала шторка-подтверждение.

### Правила списков
- Заголовок группы — `Group header="…"` (мелкие заглавные, серый), пояснение под группой — `footer`.
- Разделители рисуются автоматически между строками и начинаются после иконки.
- Прошедшее — `dimmed` (текст серым `--label-2`, иконка бледнее; не прозрачностью — иначе время и кабинет не читаются),
  текущее — `highlight` (оттенок цвета предмета через `--hl`).
- Недоступная строка — `disabled`: заголовок `--label-2`, подпись `--label-3`, иконка бледнее; метка «этап N» — в полную силу.
- Длинные списки прошедшего сворачиваются в одну строку («3 пары прошли»).

### Шторки и меню
- `openSheet({ title, content: () => <… />, onClose })` возвращает id. Закрываются свайпом вниз (за ручку или за содержимое,
  когда оно прокручено к началу), тапом по фону, «×» или Esc (Esc закрывает только верхнюю шторку);
  из кода — `dismissSheet(id)` (с анимацией). `onClose` вызывается при любом способе закрытия.
- Фон шторки — `--sheet-bg`. На ширине ≥ 768 шторка — карточка по центру, без ручки.
- Пока открыта шторка или меню, всё остальное недоступно (`inert`): Tab не уходит под затемнение.
  После закрытия фокус возвращается туда, откуда шторку открыли.
- Контекстное меню листается стрелками, Home/End. Отпускание пальца после долгого нажатия меню не закрывает.
- Контекстное меню: только действия, которые уже работают. Пункты будущих этапов не показываем.
- Неготовые функции в шторке «+» показываются серыми с меткой «этап N».

## 7. Раскладки

| Ширина | Раскладка |
| --- | --- |
| < 768 px | телефон: экран целиком, снизу стеклянная капсула с 4 вкладками и круглая «+» справа. Настройки — шестерёнка справа вверху на «Сегодня» |
| 768–1100 px | планшет: боковое меню (сворачивается в полосу иконок) + экран |
| ≥ 1100 px | широкий: меню + экран + колонка «Ближайшее» (там же открывается карточка предмета) |

- Учитываем вырезы экрана: `viewport-fit=cover`, отступы `env(safe-area-inset-*)` со всех сторон
  (боковое меню, колонка «Ближайшее», поля экрана через `--safe-l` / `--safe-r`, капсула вкладок).
- Планшет: меню и «Ближайшее» — плавающие панели с отступом 10 px (`--panel-inset`), промежутки меню ↔ экран ↔ колонка
  одинаковые. Верхняя панель экрана опущена на тот же отступ (`--navbar-top`), её кнопки стоят по краям колонки
  контента (`--pad-l` / `--pad-r`), а стекло — во всю ширину.
- «Ближайшее»: на экране «ДЗ» группа «ДЗ» скрыта (без дублей). Карточка предмета открывается в колонке с кнопкой
  «‹ Ближайшее» и закрывается сама при переходе в другой раздел.
- Низ экрана: переменная `--screen-bottom` (на телефоне — место под капсулу).
- Содержимое экрана не шире `--content-max` (720 px) и центрируется.

## 8. Навигация

- Адрес определяет экран: `#/today`, `#/week`, `#/homework`, `#/notes`, `#/settings/subjects/mss`.
- Вложенный экран въезжает справа, назад — кнопкой «‹ Назад» или свайпом от левого края (`shell/Stack.tsx`).
  Свайп срабатывает, если протянуть на треть экрана или быстро «бросить» (скорость по последним 100 мс).
- «Назад» всегда ведёт на экран, названный на кнопке (родитель), а не просто на прошлую страницу истории:
  при переходе в `history.state` запоминается, откуда пришли (`prev`); `goBack` вызывает `history.back()`, только если
  `prev` — это родитель, иначе заменяет адрес на родителя. Работает и после перезагрузки, и с системной кнопкой «Назад».
- Если «‹ Родитель» не помещается в панель, подпись становится «Назад» (как в iOS).
- Нижние экраны стека остаются живыми — при возврате сохраняется прокрутка; уходящий экран тоже не пересоздаётся.

## 9. Жесты и отклик

- Нажатие: `.pressable` (уменьшение до 0.97) для карточек и кнопок; строки списков — подсветка фона.
- Синей подсветки Android нет (`-webkit-tap-highlight-color: transparent`).
- Долгое нажатие ≈ 0,45 с (`useLongPress`), правый клик мыши — то же. Вибрирует и при системном долгом нажатии Android.
- Вибрация `haptic()` (`navigator.vibrate(10)`): переключатели, сегменты, долгое нажатие, отметка ДЗ, полный свайп.
  Выключается в настройках; где не поддерживается — ничего не происходит.

## 10. Время

- Только московское время (`src/core/time.ts`). Часы в компонентах: `useClock('minute')`, для таймеров с секундами — `useClock('second')`.
- Секундные часы — только у того, что показывает секунды. «Сегодня» пересчитывает состояние раз в минуту и просыпается
  ровно на границе пары (`TodayHero.changesAt`); каждую секунду обновляются только таймер и кольцо (`tickHero`).
- Таймер тикает раз в секунду **только пока приложение видно** (Page Visibility API).
- Таймеры и время — всегда с классом `.tabular`.

## 11. Доступность

- Все кнопки ≥ 44×44, у иконок без текста — `aria-label`.
- Фокус с клавиатуры виден (вишнёвая рамка).
- Контраст текста ≥ 4.5:1 во всех темах (проверяется тестом).

## 12. Задел на следующие этапы

- **Замены (этап 2):** изменённая пара — метка `chip--changed` (оранжевая), отменённая — зачёркнута с меткой `chip--cancelled`.
  Плашка «Временное расписание до 17.10» с иконкой Phosphor `swap` (`<Icon name="swap" weight="fill">`, как в `DayPanel`) — `--warning` на `color-mix(--warning 16%)`. Точка изменений под днём на «Неделе» — `--warning`.
- **ДЗ (этап 3):** `SwipeRow` как в «Почте»: вправо — «Сделано» (`--success-fill`), влево — «Перенести» (`--warning-fill`)
  и «Удалить» (`--danger-fill`, с подтверждением). Полный свайп выполняет действие. Просроченное — `--danger`.
  Счётчик невыполненных — `Badge` на вкладке «ДЗ».
- **Статистика (этапы 3–4):** `ActivityRings` (сделано из заданных, вовремя) + «серия дней без просрочек».
- **Цифра на иконке приложения:** `navigator.setAppBadge(n)` с проверкой поддержки.
  Работает в Chrome/Edge на Windows и macOS для установленного приложения; **в Chrome на Android не поддерживается**
  (Android сам ставит точку только при уведомлениях). Внутри приложения счётчик на вкладке работает везде.

## 13. Чек-лист нового экрана

1. Экран обёрнут в `Screen` (большой заголовок, при вложенности — `back`).
2. Контент — `Group`/`Cell`, цвета и размеры шрифта только из токенов (тест `style-rules` проверяет оба правила),
   предметы через `useSubject`.
3. Время с `.tabular`, кнопки ≥ 44 px, `aria-label` у иконок.
4. Проверен в светлой, тёмной и AMOLED темах, на телефоне 412×915 и планшете 1340×840 (скриншоты Playwright).
5. Есть пример экрана на странице превью.
