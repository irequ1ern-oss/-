# Статус Requiem

| Этап | Доступно в коде | Граница текущей версии |
| --- | --- | --- |
| 0. Аудит | Архитектура, разделение данных, исходные тесты, последовательность миграции | Отдельно проверяется размещение и доступ с реального устройства |
| 1. Foundation | Проверка ролей на сервере, сессии, выход, смена пароля и однократная активация. Четыре контекста, настройка порядка, ширины и видимости карточек, командная палитра | Настоящий пароль выбирает владелец |
| 2. Академическое ядро | Отметки урока и дня, оценки, требования по предмету, обязательные работы, задачи, развитие проектов через зависимости, вложения, долги и частные наблюдения | История начинается с отметок владельца. Опоздания считаются присутствием. Неотмеченные и уважительные исключаются из процента |
| 3. Расчёты | Бюджет в уроках/минутах, резерв, ручные цели, повторяющиеся пропуски, строгие ограничения, прогноз оценок при равных весах, стратегии, симуляция и сохранение решения | Последовательный подбор на период — эвристика. Дневные сценарии включают поздний приход, ранний уход и одиночные пропуски. Ручная симуляция поддерживает произвольное сочетание. Показатель риска является условным |
| 4. Транспорт и время | Два направления, датированные рейсы и отмены, импорт/обновление, пороги посадки, сравнение с задержкой выхода на 10 минут, категории времени, исключение пересечений | Встроенного потока текущих рейсов перевозчика нет. Ручной ввод, разрешённый JSON-источник и прогнозы по имеющимся данным. Регулярное расписание из фотографии не генерируется |
| 5. Shay | Три API-провайдера, схемы инструментов, ограничение циклов/токенов, условия доступа к источникам, предложения изменений и одноразовое подтверждение, память и история | Выполнены воспроизводимые тесты протокола на контролируемом ответе. Настоящая генерация требует ключа и модели. Поток текста и вызовы инструментов отображаются во время генерации, поддержаны остановка, временное текстовое вложение, выбор контекста и боковая панель. Календарные напоминания сохраняются как задачи. Анализ изображений и голос отсутствуют |
| 6. Oracle и Blackbox | Серверный планировщик, правила с AND/OR, тихие часы, дедупликация и журнал, push-очередь с повтором, уведомления в приложении, сравнение факта и прогноза | Доставка Web Push на устройство требует разрешения браузера и VAPID. Набор триггеров ограничен утренним/вечерним обзором, выходом и дедлайном. Правила не вызывают друг друга |
| 7. Экосистема | Markdown, ссылки Obsidian, GitHub только на чтение для выбранного владельца, записи времени/сна, данные семестров, флаги интерфейса и эксперимента, администрирование календаря и каталога | Связь с Металлоатласом через ссылки. Двусторонней записи в хранилище Obsidian, семантического индексатора и переноса завершённого семестра одним действием пока нет |
| 8. Эксплуатация | Две сборки, API-тесты, миграции, Docker, резервирование SQLite, защита приватного API от кеширования. Шифрованный снимок дня и офлайн-черновики задач с повторяемой синхронизацией | Офлайн-копия по желанию защищается отдельной фразой. История чата, произвольные вложения и весь журнал посещений не копируются на устройство. Проверку на физическом Android-планшете и доставку push фиксируем отдельно |

## Где искать код

- Публичная интеграция — src/main.tsx, src/data/calendar.ts, src/views/settings/SettingsView.tsx, vite.config.ts.
- Личный интерфейс — account/index.html, src/requiem. Чистые расчёты — server/engine.py и общий звонковый справочник data/bells.json.
- Данные, сессии, доступ и маршрутизация — server/db.py, server/migrations, server/auth.py, server/claim.py, server/workspace.py.
- Shay, память, материалы, вложения — server/assistant.py, server/resources.py, server/extras.py.
- Уведомления и транспорт — server/oracle.py, server/push.py, server/feed.py.
- Сборка и выпуск — Dockerfile, railway.toml, .github/workflows, scripts/account-worker.mjs.
- Приёмка — npm run check, npm run build, npm run build:account, python -m unittest discover -s server -t . Проверки работают с изолированными тестовыми данными. Запуск и настройки владельца приведены в OPERATIONS.md.

## Следующая приёмка

На устройстве владельца пройти первую активацию, установить фразу офлайн-доступа, сравнить живую поездку с прогнозом и принять тестовое push-уведомление. Для проверки Shay подключить выбранную разрешённую модель. Следом — сравнение недельных прогнозов с реальными решениями и контрольными работами.
