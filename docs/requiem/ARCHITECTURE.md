# Requiem · аудит и архитектура

Исходная точка — 947b563, ветка main. До изменений прошли 360 тестов Vitest, tsc и production-сборка. Проверены точки входа приложения и превью, модули core, state, shell, views, data, PWA, манифест кеша, зависимости и оба workflow.

Гостевой интерфейс — Preact, TypeScript, Vite и Workbox на GitHub Pages. Календарь использует московский часовой пояс, JSON основного расписания, датированные замены и приоритет отмен. Составные пары уже содержат границы уроков. Личные настройки живут в localStorage, домашние задания и заметки — в IndexedDB с журналом восстановления. Для приватного контура переиспользуем расписание группы, интервалы звонков, шрифт и сборку.

## Обнаруженные ограничения

* Проверка имени, hash-адрес и выбор экрана не дают полномочий. Серверных учётных записей в исходной версии нет.
* Основные данные о предметах и шаблон недели включены в публичный бандл. Личные наблюдения, логины, маршруты владельца и ключи нельзя добавлять туда или в публичный git.
* Существующий service worker перехватывает навигацию. Вход и запросы приватного API требуют отдельной границы кэширования.
* Браузерный журнал общего приложения привязан к устройству. Автоматическая отправка его содержимого под новым аккаунтом могла бы перенести чужие записи с общего планшета.
* Превью и параметр now эмулируют время. Сервер использует собственные часы для реальных отметок и сессий.
* Тесты исходной версии в основном проверяют функции. Интеграционных проверок ролей, хранения на сервере и конфликтов записи до изменений не было.
* SVG в общем компоненте Icon берётся из встроенного каталога. Пользовательский Markdown и ответы модели должны отображаться как текст без исполнения HTML.

## Границы системы

GitHub Pages продолжает отдавать публичный интерфейс. Полная сборка того же репозитория может обслуживаться FastAPI по HTTPS. Из настроек Pages пользователь переходит на заранее заданный адрес аккаунта. Пароль и cookie остаются на одном origin с API. На серверном хосте доступны оба интерфейса. Для личной установки выбрана SQLite на постоянном диске, один экземпляр сервера, WAL, миграции и резервное копирование средствами SQLite. Внешний провайдер БД не обязателен.

Поведение гостевой базы при обновлении не меняется. Новая серверная база создаётся отдельно. Пользователей создаёт оператор сервера локальной командой. Роли назначаются вне веб-интерфейса. Браузер получает только данные текущего пользователя. Изменения записей проверяют ожидаемую версию. Приватное содержимое не попадает в кеш Workbox.

## План поставки

1. Вход, роли, отзыв сессий, личное рабочее пространство и миграция первой схемы.
2. Журнал уроков, академические сведения, задачи, наблюдения и бюджет посещаемости.
3. Чистые функции расчёта, явные стратегии, сценарии и ограничения.
4. Датированные рейсы, личные настройки поездки, временные пороги и журнал времени.
5. Серверный доступ к языковым моделям, узкие инструменты, подтверждение изменений и память.
6. Правила, уведомления, журнал решений и проверка прогнозов.
7. Связанные материалы, архив, расширение рабочего пространства и административные операции.
8. Приёмочные проверки, обновление, резервирование и эксплуатация.

Производственные секреты вводит владелец хоста. Публичный сайт и браузер никогда не получают API-ключи. Граница готовности каждой функции фиксируется в IMPLEMENTATION_STATUS.md.
